# Team Platform

Фронтенд платформы для поиска IT-проектов, команд и развития через практику.

## Стек

### Основной стек и инструменты для верстки

* Next.js
* TypeScript
* Tailwind CSS
* shadcn/ui
* Lucide Icons

### Работа с формами

* Shadcn/ui Fields
* React Hook Form
* Zod

### Работа с данными

* TanStack Query
* Axios

### Управление состоянием

* Zustang
* Local State

### Маршрутизация

* Next.js App Router

### Работа с API

* REST API
* HTTP-запросы через Axios
* Типизация запросов и ответов с TypeScript

### Статус проекта

Проект находится в стадии разработки.

Основной приоритет на текущем этапе — создание MVP платформы и реализация базовых пользовательских сценариев:

- регистрация и авторизация;
- каталог проектов, создание и редактирование, участники, навыки, вакансии, заявки и приглашения;

Подробная документация раздела проектов: [PROJECTS.md](./PROJECTS.md).

## Вход и регистрация

### Админ-панель

1. Запустите фронтенд командой `npm run dev` и войдите в аккаунт TeamPlatform с ролью `ADMIN`. Если роль ещё не назначена, передайте бэкенд-разработчику свой username.
2. Откройте `/admin` или выберите «Админ-панель» в профиле. На телефоне пункт называется «Панель».
3. «На платформу» возвращает в профиль. «Выйти из аккаунта» завершает сессию.

Обзор рассчитывает показатели по текущим записям каталогов проектов, идей и сообществ. Дни на графике считаются по московскому времени. На страницах каталогов доступны поиск и фильтр «Мои записи».

Сервер Next.js получает актуальную роль через `GET /api/auth/me` при открытии страницы и перед каждой операцией записи. Если проверка недоступна, доступ закрыт. Операции выполняются с персональным токеном пользователя. Текущий Express API разрешает редактирование и удаление только автору проекта или идеи и создателю сообщества. Для модерации чужих записей бэкенду нужна поддержка роли `ADMIN` в соответствующих операциях.

### Авторизация

Фронтенду нужны `NEXT_PUBLIC_API_URL` (адрес бэкенда без `/api`), `AUTH_SECRET`,
`AUTH_GITHUB_ID`, `AUTH_GITHUB_SECRET` и серверный `AUTH_INTERNAL_SECRET`.
Задайте `AUTH_URL` равным адресу фронтенда (локально, например, `http://localhost:3000`) и открывайте сайт по этому адресу. В GitHub OAuth App укажите callback `<адрес фронтенда>/api/auth/callback/github`.

Регистрация использует подтверждение почты через шестизначный код. Дополнительный
флаг на фронтенде для этого не требуется. Контракт бэкенда:

- `POST /api/auth/register` принимает `{ email, username, password, locationId }`.
  При `201` открывается модалка. `verificationEmailSent: false` показывает сообщение
  о созданном аккаунте и сбое отправки письма.
- `POST /api/auth/verify-email` принимает `{ email, code }`, где код передаётся
  строкой с сохранением ведущего нуля. После `204` фронтенд входит с введённым
  паролем и возвращает пользователя на запрошенную страницу. Если создание сессии
  не удалось, открывается форма входа с сообщением об успешном подтверждении.
- `POST /api/auth/resend-verification` принимает `{ email }`. Ответ `202` означает
  принятие запроса. Интерфейс показывает нейтральное сообщение и таймер на 60 секунд.
  Таймер сохраняется при закрытии модалки и перезагрузке вкладки. Пароль хранится
  только в памяти формы.
- `POST /api/auth/login` с ответом `403` и `code: "EMAIL_NOT_VERIFIED"` открывает
  подтверждение почты. Правильный пароль необходим и для продолжения этого сценария.

Код действует 10 минут. После пяти неверных попыток понадобится новый код.
Срок действия, одноразовость и ограничения проверяет бэкенд. Для доставки писем
на бэкенде должны быть настроены `RESEND_API_KEY`, `EMAIL_FROM` и
`EMAIL_VERIFICATION_SECRET`, а миграция подтверждения почты должна быть применена.
